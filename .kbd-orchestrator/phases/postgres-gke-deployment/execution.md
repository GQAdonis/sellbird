## Task boundary model

Workers implement a whole change and return per-task evidence. The driver then records each task in order with `kbd-apply begin-task` / `end-task` (backend IDs 1..N), so canonical completion follows the worker's evidence rather than the worker's own claim. Workers never edit `tasks.md` checkboxes, run tests, builds or compilers (VLBV: generated code runs only at B4), or touch paths outside their change's ownership. `openspec validate` is allowed.
