# Design: Sellbird's flint-gate route, claims and local Kratos/flint-gate stand-in

## Context

See the phase assessment (`.kbd-orchestrator/phases/postgres-gke-deployment/assessment.md`) and plan (change 7). Operator decisions D1–D12 and the plan-stage decisions (restated goals adopted, single tenant with RLS deferred, production overlay in the platform repository) apply.

## Decisions

Write infra/flint-gate/sellbird-routes.yaml: kratos_session auth, a claims_enhancement hook minting an RS256 JWT with aud=sellbird and TTL of 300 s or less, passthrough for Kratos self-service routes, and no admin-port exposure. Add a local stand-in (compose file under infra/local/) running the flint-forge PG18 image, Kratos with registration disabled and a minimal email+password+TOTP schema, flint-gate with the route, and Sellbird in gateway mode, so the auth path is verified against real services before the platform exists. The compose file builds Sellbird from the Dockerfile owned by change 6 (cluster-ready-container-image), pins the flint-forge and flint-gate images by digest, and gates startup on health checks. A one-shot migrate service runs `sellbird storage migrate` with the migration-role DSN before Sellbird starts with the app-role DSN. Local credentials come from an uncommitted .env generated by a script, never from tracked files.

### Route file (7.1)

- Written against flint-gate's real schema (`crates/flint-gate-core/src/config/types.rs` at the reference checkout), not the older skill examples. The file holds only `sites` and `routes`: site `sellbird`, `domains: ["sellbird.example.test"]`, `default_auth: kratos_session`, `default_upstream: http://sellbird.sellbird.svc.cluster.local:5555`; routes `sellbird-api` (`/api/**`, priority 20) and `sellbird-dashboard` (`/**`, priority 10), both `methods: []` (all), both with `claims_enhancement` → `mint_jwt.enabled: true`, `additional_claims: {aud: "sellbird", aal: "{{ identity.aal }}"}`. flint-gate merges additional claims last, so `aud` is a single string that a trait cannot override; `sub` is `identity.id`; the `kid` header is the signing key's id.
- TTL ≤ 300 s is the platform's `jwt.default_ttl_seconds` (the hook has no per-route TTL). The local stand-in sets 300.
- Kratos self-service passthrough is an `anonymous` provider on a separate `auth.example.test` site in the stand-in's platform half (`infra/local/flint-gate/base.yaml`), not in the route file: the contract forbids passthrough routes on the Sellbird site and gives the auth host to the platform.
- No Cedar `authorize` hook and no `stream` block: authorization is Sellbird's `sub` allowlist per the contract (an empty gate policy set is default-deny); Sellbird serves no SSE. Both are recorded in `infra/flint-gate/README.md`.
- Facts from the flint-gate source that the skills state differently: the config is read once at startup (the watcher only signals that a restart is needed; no hot reload); the JWKS at `/.well-known/jwks.json` is served from the database table `jwt_signing_keys`, so an RS256 key must be seeded with `flint-gate --database-init-only` plus `FLINT_GATE_JWT_PUBLIC_KEY_PATH`; site domains match the `Host` header exactly (port included); the client `Host` header is forwarded upstream unchanged; client `x-flint-*` headers are stripped and `Authorization` is replaced by the minted token; `admin_listen` defaults to loopback and a non-loopback bind without `admin_auth` is refused.

### Kratos (7.2)

- Registration and recovery (and verification) disabled; password, TOTP and lookup secrets enabled; `session.whoami.required_aal` and `selfservice.flows.settings.required_aal` are `highest_available`; cookie domain `example.test`, `SameSite=Lax`, lifespan 24 h; HIBP check off (no outbound calls). DSN from the `DSN` env var; cookie/cipher/default secrets in a second `-c` file generated per run. Admin API only on the compose network. Image `oryd/kratos:v1.3.1`.
- **Deviation:** Kratos's admin create body has no `id` field, so the operator identity cannot get the fixed placeholder id `00000000-0000-4000-8000-000000000001`. `create-identities.sh` creates `operator@example.test` and `other@example.test` (password credential only, sent on stdin from a pinned curl container on the compose network) and returns the generated ids; `make-env.sh` writes the operator's id into the uncommitted `.env` as `SELLBIRD_GATE_ALLOWED_SUBS` / `SELLBIRD_E2E_ALLOWED_SUB`. The placeholder stays in docs only.
- `session.cookie.secure` / `http_only` from the contract table have no Kratos config key: Kratos always sets `HttpOnly` and sets `Secure` unless started with `--dev`. The stand-in does not use `--dev`.

  - Kratos: `oryd/kratos@sha256:fe2428f103a6240c064b6ea77d3088610865c55fcebccb30355857eccdc25b4b` (v1.3.1).
  - Admin client tool: `curlimages/curl@sha256:935d9100e9ba842cdb060de42472c7ca90cfe9a7c96e4dacb55e79e560b3ff40` (8.17.0).
  - Sellbird: local `sellbird:boundary`, `pull_policy: never`.
- Provisioning runs once, as a first-init script in the Postgres container (`/docker-entrypoint-initdb.d/50-sellbird-local.sh`, after the image's own 01/02 and before its 99 assertion): `infra/postgres/provision.sql` unmodified, then `sellbird_test` (same owner, grants, settings), then the `kratos` and `flintgate` roles/databases. `POSTGRES_DB=flint` because the image preloads pg_cron/pg_net for that database. Kratos runs `migrate sql` before `serve` in the same container; flint-gate runs `--database-init-only` (migrations + key seed, idempotent upsert by kid) before serving. The only one-shot service is `sellbird-migrate` (`storage migrate`, `SELLBIRD_MIGRATE_DATABASE_URL` only); `sellbird` waits for it with `service_completed_successfully` and for flint-gate's health, which requires the per-run `kid` in the JWKS.
- Sellbird runs as the boundary image does in `check_container.sh`: read-only rootfs, `tmpfs /tmp:rw,exec,nosuid,nodev`, named volume at `/data`, `cap_drop: ALL`, `no-new-privileges`, args `dashboard --host 0.0.0.0 --port 5555`, gateway env per the contract (`SELLBIRD_DASHBOARD_MODE=gateway` set in the compose file only, never in `.env` or the host shell), app-role DSN only. Network aliases `sellbird.sellbird.svc.cluster.local` and `flint-gate.flint-gate.svc.cluster.local` let the route file and the JWKS URL be used verbatim.
- Host ports, loopback only: 4456 (flint-gate), 5555 (Sellbird direct, for the e2e negative controls), 55432 (Postgres, for the storage suite). Kratos public/admin and flint-gate admin are not published.
- Kratos and flint-gate run as the invoking user's uid/gid (`LOCAL_UID`/`LOCAL_GID`), so the 0600 generated key and secrets files are readable on Linux bind mounts without loosening their modes.

### How make-env.sh obtains the session cookies

After `docker compose up -d --wait postgres kratos flint-gate`, `scripts/local/kratos_session.py` (stdlib only) talks to Kratos's public API through flint-gate's auth-host passthrough (`http://127.0.0.1:4456`, `Host: auth.example.test`) using browser flows with `Accept: application/json`: (1) `GET /self-service/login/browser`, `POST /self-service/login?flow=…` with `method=password` and the CSRF token → aal1 `ory_kratos_session`; (2) `GET /self-service/settings/browser`, read the `totp_secret_key` node, `POST /self-service/settings?flow=…` with `method=totp` and an RFC 6238 code → TOTP enrolled; (3) wait for the next 30 s step, `GET /self-service/login/browser?aal=aal2`, `POST` with `method=totp` → the session upgraded to aal2; (4) `GET /sessions/whoami` must report aal2. Cookies are tracked by hand (Kratos marks them `Secure` and scopes them to `example.test`, which a cookie jar would not send to a plain-HTTP loopback port). The `Cookie` header values go only into `infra/local/.env`.

### Boundary commands

- run: `scripts/local/make-env.sh && docker compose -f infra/local/compose.yaml up -d --wait` (as adopted).
- storage suite: `scripts/local/dsn.sh migrate|app` prints DSNs for **`sellbird_test`**, not `sellbird`: the suite drops and recreates Sellbird's schema, which would break the running container before the e2e step. `dsn.sh migrate sellbird` reaches the app's database if ever needed.
- e2e: the adopted command sets only `SELLBIRD_GATEWAY_URL`, but the test requires every `SELLBIRD_E2E_*` variable once that is set. They live in `infra/local/.env`; run it as `SELLBIRD_GATEWAY_URL=http://localhost:4456 scripts/local/e2e-env.sh .venv/bin/python -m pytest -q tests/test_gateway_mode_e2e.py` (exports only `SELLBIRD_E2E_*` and `SELLBIRD_GATEWAY_URL`, unsets `SELLBIRD_DASHBOARD_MODE`). The lead/QA owns the packet wording.

## Risks

- Real names: no real person's or business's name, email, phone, address or domain in code, tests, docs or commits; use fictional example.com / example.test data.
- Secrets: credentials only through operator-created Secrets or an uncommitted local .env.
- Not executed before the boundary (VLBV): no container, compose file or script here has been run. Unverified assumptions that a B5 repair may need to touch: Compose's `up --wait` accepting the exited-0 `sellbird-migrate` that `sellbird` depends on with `service_completed_successfully` (older Compose releases fail `--wait` on any exited container); Kratos v1.3.1 accepting the plain-HTTP browser flows through the gate without `--dev`, and its `totp_secret_key` node shape; flint-gate (amd64) under emulation on arm64 hosts; arbitrary `LOCAL_UID` for the Kratos and flint-gate images.
- `make-env.sh` deletes the stand-in's own containers and volumes (`docker compose -p sellbird-local down -v`) at the start of every run, because Postgres only reads passwords when its volume is created.
- Session cookies in `.env` expire after Kratos's 24 h lifespan; rerun `make-env.sh` before a later boundary attempt.
- Local DSNs use `sslmode=disable` (loopback, no TLS); the hosted contract requires `require` or stronger.
