# Design: Sellbird's flint-gate route, claims and local Kratos/flint-gate stand-in

## Context

See the phase assessment (`.kbd-orchestrator/phases/postgres-gke-deployment/assessment.md`) and plan (change 7). Operator decisions D1–D12 and the plan-stage decisions (restated goals adopted, single tenant with RLS deferred, production overlay in the platform repository) apply.

## Decisions

Write infra/flint-gate/sellbird-routes.yaml: kratos_session auth, a claims_enhancement hook minting an RS256 JWT with aud=sellbird and TTL of 300 s or less, passthrough for Kratos self-service routes, and no admin-port exposure. Add a local stand-in (compose file under infra/local/) running the flint-forge PG18 image, Kratos with registration disabled and a minimal email+password+TOTP schema, flint-gate with the route, and Sellbird in gateway mode, so the auth path is verified against real services before the platform exists. The compose file builds Sellbird from the Dockerfile owned by change 6 (cluster-ready-container-image), pins the flint-forge and flint-gate images by digest, and gates startup on health checks. A one-shot migrate service runs `sellbird storage migrate` with the migration-role DSN before Sellbird starts with the app-role DSN. Local credentials come from an uncommitted .env generated by a script, never from tracked files.
