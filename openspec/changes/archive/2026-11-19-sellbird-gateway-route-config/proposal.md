# Sellbird's flint-gate route, claims and local Kratos/flint-gate stand-in

## Why

Write infra/flint-gate/sellbird-routes.yaml: kratos_session auth, a claims_enhancement hook minting an RS256 JWT with aud=sellbird and TTL of 300 s or less, no passthrough on the Sellbird host (Kratos self-service passthrough belongs to the platform's auth host, per design.md), and no admin-port exposure. This change serves phase goal G5 (restated) of KBD phase `postgres-gke-deployment`.

## What Changes

Write infra/flint-gate/sellbird-routes.yaml: kratos_session auth, a claims_enhancement hook minting an RS256 JWT with aud=sellbird and TTL of 300 s or less, no passthrough on the Sellbird host (Kratos self-service passthrough belongs to the platform's auth host, per design.md), and no admin-port exposure. Add a local stand-in (compose file under infra/local/) running the flint-forge PG18 image, Kratos with registration disabled and a minimal email+password+TOTP schema, flint-gate with the route, and Sellbird in gateway mode, so the auth path is verified against real services before the platform exists. The compose file builds Sellbird from the Dockerfile owned by change 6 (cluster-ready-container-image), pins the flint-forge and flint-gate images by digest, and gates startup on health checks. A one-shot migrate service runs `sellbird storage migrate` with the migration-role DSN before Sellbird starts with the app-role DSN. Local credentials come from an uncommitted .env generated by a script, never from tracked files.
